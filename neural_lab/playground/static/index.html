What is real here: every plane, bar and number is computed by the published model in your browser (two ONNX files exported from its weights and checked against the deployed model and PyTorch). Planes show each layer's five most active channels for this weld, coloured on that layer's own scale; small bars are per-channel mean activations. The dotted lines only show the order of operations. The latent universe. 3,019 welds, as the network sees them.

Each point is a real test tile, placed by the 32 numbers the encoder compressed it into, then projected to 3D (or 2D) with PCA. Colours are the true classes: the network never saw these labels. Drag to turn, hover to see a tile, click to load it.

PCA is a linear projection of 32 dimensions down to 3 or 2: points that look close may differ in the dimensions that are not shown. The slow turn of the 3D view is a camera move only.

Is it a neural network? The evidence, not a claim.

Yes: a convolutional autoencoder. Below, its layers are read straight from the published weight file, it is compared live with an untrained copy of itself, and its training record is shown. Every number comes from the files or from inference.

What the first layer learned

The first layer is 32 small 3×3 filters slid over the weld. Orange = positive weight, blue = negative. Trained filters show organised patterns; the untrained twin's are random. We do not claim what each filter means.

How it was trained

    for x in batches_of_sound_welds:
    loss = mse(model(x), x)   # 1 redraw, measure the error
    optimizer.zero_grad()
    loss.backward()           # 2 backpropagation: blame per weight
    optimizer.step()          # 3 nudge all 718,369 values

    Made by python -m neural_lab.playground.proof from the published weights and the test welds. No retraining: the untrained twin is a control, built with the same code and random starting values.
